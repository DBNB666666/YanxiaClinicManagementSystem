# 已知问题与限制（v0.0.1）

## 环境/验收限制

1. **本开发会话无法启动 Electron GUI**
   - 本机 Electron 主进程在 `app.whenReady` 前无法完成窗口初始化（当前会话环境限制，Electron 进程启动后 ready 事件不触发）。
   - 因此“Electron 窗口内的实际点击/系统打印对话框”未在本会话人工验证。
   - 已用本机 Edge + Playwright 跑同一套渲染页面和真实 `ClinicService`/sql.js 服务，覆盖 14 条 UI 场景；核心业务另有 37 条 Vitest 用例。
   - 交付前建议在目标 Windows 电脑上按 `docs/ACCEPTANCE_REPORT.md` 的“手工验收”再走一遍窗口、系统打印和 125%/150% 缩放。

2. **打印按钮走 PDF 阅读器**
   - “打印”生成 A5 PDF 后调用系统默认 PDF 阅读器打开，由用户在阅读器里按 `Ctrl+P` 打印；没有直接弹 Electron 打印对话框。若需要一键系统打印对话框，后续可加。

3. **未做代码签名**
   - zip 未签名，Windows SmartScreen 可能提示“未知发布者”。

4. **图标**
   - 当前使用 Electron 默认图标，未做诊所品牌图标。

## 功能限制

- 没有登录、云同步、手机版、多设备共享。
- 没有患者档案/病历/预约；患者信息只跟着处方。
- 没有药品批次、效期、条码、供应商独立管理。
- 进货记录只追加，不提供编辑/删除。
- 财务只支持日/周/月/年，不支持自定义日期区间。
- 通知只在软件内，不做系统托盘/手机推送。
- 数据文件未加密；备份文件含患者信息，请妥善保管。
- sql.js 采用“内存库 + 整库原子写文件”；1000 张处方规模已测试，数据量特别大时保存会变慢，后续可换 better-sqlite3（Repository 接口不变）。

## 已知小问题

- 处方编辑页的库存提示用的是进入页面时的库存快照；如果同时在别处进货，需要重新进入页面刷新。
- 药房卡片上的“停用”入口会先进入详情页，再由详情页停用，不是卡片上直接停用。
- 深色/阅读模式下打印预览的纸张始终为白色（符合预期）。
